# EvalEx-j8：可配置公式与条件

`EvalEx-j8` 用于解析并执行数学、布尔及其它已验证类型的表达式，让服主能够在配置中调整价格、奖励、冷却、概率、条件或数值算法。它负责表达式求值，不负责权限、经济事务、持久化、配置迁移或 Bukkit 线程安全；这些仍由插件业务层控制。

使用本库前阅读 `README.md`，并为每个配置公式定义业务语义、变量表、单位、允许结果范围、精度规则和失败回退。不能把“表达式可计算”当作“结果可以直接应用”。

## 依赖与打包

已核对的 Maven Central 示例坐标是 `top.mrxiaom:EvalEx-j8:3.6.1`。新项目或升级项目仍须先从 `build.gradle.kts` 锁定实际版本，并按该版本 POM、sources/Javadoc 复核构件与 API：

```kotlin
repositories {
    mavenCentral()
}

dependencies {
    implementation("top.mrxiaom:EvalEx-j8:3.6.1")
}
```

该库会在插件运行时直接执行，应作为 `implementation` 处理并进入 Shadow JAR。按项目私有 `shadowGroup` 重定位实际包前缀；重定位目标、内部服务文件与资源处理必须以锁定版本构件为准，不得照搬记忆中的包名：

```kotlin
tasks.shadowJar {
    relocate(
        "com.ezylang.evalex",
        "$shadowGroup.libs.evalex"
    )
}
```

构建后检查最终 JAR：库应存在于重定位后路径，`org/bukkit/`、`io/papermc/paper/` 和 `agent-dev/` 不得被打入。若项目已将该库交由其它受控类加载方案提供，记录例外和冲突风险，不要同时嵌入两个版本。

## 配置公式契约

每一个公式配置键都应有明确契约，而不是泛化的“任意表达式”字符串。至少定义：

| 项 | 必须明确的内容 |
| --- | --- |
| 用途 | 该结果用于价格、奖励、概率、条件或展示；不得同时承担不相容业务语义。 |
| 变量 | 名称、类型、单位、来源、可取范围与缺失行为，例如 `level`、`amount`、`base`。 |
| 结果 | 期望类型、最小/最大值、小数位、舍入方式、`null`/非数字/无穷大等异常值处理。 |
| 语法 | 允许的函数、运算符、数组或结构能力；业务不需要时不要开放。 |
| 生命周期 | 首次加载、配置重载、缓存替换与公式错误时继续使用旧值还是禁用该功能。 |
| 错误 | 日志应包含配置文件、键、表达式位置和期望类型；不要泄露与公式无关的敏感变量。 |

推荐将原始配置、已解析表达式、变量绑定与结果校验封装进不可变的领域对象，例如 `config/formula/PriceFormula`。业务调用只接收已经验证的输入与输出，不直接在命令、监听器或箱子容器菜单点击回调内解析 YAML 字符串。

## 受限求值流程

对管理员可编辑的公式按以下顺序处理：

1. 读取字符串后检查长度、空值和项目定义的允许字符/语法范围；空公式使用明确默认值或给出配置错误，不能悄悄按零处理。
2. 按锁定版本 API 解析 `Expression`；解析异常记录配置位置并使该条规则不可用或保留已验证的旧快照。
3. 只传入该公式契约允许的变量。变量来自玩家、物品、数据库或其它插件时，先做类型、权限、缺失和范围验证；客户端或配置文本不能直接成为可信数值。
4. 用锁定版本文档确认的 `with(...)`、`withValues(...)` 或等价 API 绑定变量并执行；不凭示例记忆猜测重载。
5. 将 `EvaluationValue` 显式转换为预期业务类型，再检查正负、上下界、精度、舍入与溢出。货币和精确数值使用 `BigDecimal` 与项目声明的 `MathContext`/舍入规则，避免先转 `double` 再恢复精度。
6. 只有全部校验成功后，才把结果交给经济扣款、奖励发放、概率分支或显示逻辑。权限、余额、库存容量、冷却和事务检查必须在应用结果前后按业务语义独立执行。

一个最小的数值计算形态如下；类名和访问器须按项目锁定资料核验：

```java
Expression expression = new Expression("base * (1 + level / 10)");
EvaluationValue value = expression
        .with("base", new BigDecimal("100"))
        .and("level", level)
        .evaluate();
BigDecimal price = value.getNumberValue();
```

示例只展示计算形态，不代表变量、舍入、异常和经济事务已完成。实际实现必须补齐上述公式契约。

## 缓存、并发与性能

解析表达式比使用已解析对象成本更高。可在配置加载阶段完成解析并缓存语法树，但可变变量值不得在多个玩家、请求或线程之间共享。上游说明支持通过 `Expression#copy()` 在复用已解析表达式的同时，以每次求值独立副本绑定变量；其线程安全范围、复制时机和方法签名必须按锁定版本资料确认。

- 主线程上的命令、事件和菜单点击仅执行有界、快速的公式计算；复杂批量计算应在已验证的异步数据快照上完成，再通过 PluginBase 调度器回到允许访问 Bukkit 对象的执行路径。
- 不在高频事件、每格菜单刷新、每个网络包或循环中反复解析同一公式。
- 重载时原子替换整组已验证公式快照；新配置有错误时按项目契约保留旧快照或禁用相应功能，不能让部分新旧规则混用。
- 停用时取消等待公式结果的任务；异步计算返回前重新确认插件仍启用、玩家/目标仍有效、配置版本尚未失效。

## 不应使用的场景

- 不能以公式替代 Java 的权限、物品所有权、数据库事务、经济扣款、反作弊或跨服一致性检查。
- 不能将表达式文本作为 Java、JavaScript、命令、反射类名、数据库语句或文件路径执行。
- 不能仅因某函数在较高版本文档中存在就写入低版本项目；升级前按精确构件版本比较资料。
- 不能用宽泛 `try/catch` 将解析或求值失败静默转换为奖励、免费价格或默认通过条件。

## 最低验证

1. Gradle 从 Maven Central 解析项目锁定的 `EvalEx-j8` 坐标；复核 POM、sources/Javadoc、许可证和实际包前缀。
2. Shadow JAR 中仅存在重定位后的实现依赖，没有服务端 API、开发资料或意外的重复版本。
3. 为每个业务公式测试正常值、缺失变量、错误语法、错误类型、边界值、负数、极大值和舍入边界；错误应定位到配置键且不触发业务副作用。
4. 货币、奖励和概率等关键业务路径验证结果范围、精度、事务/权限检查及失败回退，而不仅是公式输出。
5. 重载时验证已解析缓存替换和错误配置处理；并发或异步路径验证表达式副本、数据快照和停用后的结果失效。
