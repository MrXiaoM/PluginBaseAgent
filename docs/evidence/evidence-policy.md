# 接口证据政策

Minecraft 服务端插件没有覆盖所有场景的单一稳定标准；Spigot、Paper、PluginBase、外部插件与 NMS 都可能按版本变动。本项目因此采用“证据优先”政策：会影响代码正确性、兼容性或运行时类加载的结论，必须能够追溯到精确版本资料。

## 哪些结论必须取证

| 范围 | 需要证明的内容 |
| --- | --- |
| Spigot/Paper API | 类型存在性、成员签名、事件语义、弃用/实验性、线程和版本边界 |
| PluginBase | 模块存在性、Options、生命周期、Holder 自动注册、调度器、工厂、配置和打包行为 |
| Gradle/Shadow | 插件版本 API、依赖范围、任务配置、资源合并和重定位语义 |
| 外部插件 API | 坐标、类名、支持版本、可选依赖加载边界 |
| NMS/CraftBukkit/反射 | 精确类/成员、映射、实现版本与回退策略 |
| 配置/资源格式 | 框架或项目版本实际支持的字段、序列化和迁移行为 |

纯项目内部业务算法可不逐个记录外部证据，但一旦引用上述边界，必须补充证据。

## 可接受来源优先级

1. **目标项目实际解析的运行 JAR 字节码**：公开类型、字段、构造器、方法签名和继承关系的唯一权威来源。
2. **同版本 sources 归档**：最适合确认注解、实现细节、参数语义与项目可见源码。
3. **同版本 Javadoc 归档**：最适合确认公开契约、说明和弃用信息。
4. **构件元数据与 POM/module 文件**：用于确认坐标、变体、sources/Javadoc 产物和仓库信息。
5. **官方/上游仓库中特定 tag/commit 的源码**：只在其版本与目标构件可确定对应时使用。
6. **Vineflower 对索引主 JAR 的临时反编译**：只用于理解实现；不能覆盖字节码签名，也不能单独证明兼容性或线程语义。
7. **已有项目代码**：只能作为风格和集成参考，不能单独证明 API 在当前目标版本存在。

网络搜索摘要、博客、论坛、问答、AI 记忆、旧版示例和 IDE 自动补全不可单独作为接口证据。

## 精确版本要求

每份证据至少描述：

- 生态：Spigot、Paper、PluginBase、外部插件或 NMS；
- 构件坐标/版本，或明确的服务端/映射版本；
- 资料类型：sources、Javadoc、元数据、已锁定源码；
- 来源位置：GAV、构件 `SHA-256`、归档内路径、Javadoc 锚点、URL 或版本控制标识；
- 内容哈希或能识别 Snapshot 内容变化的信息；
- 查询的类、成员或行为；
- 得出的结论和不覆盖的边界。

`1.20`、`最新版本`、`Paper` 等模糊名称不能替代精确证据。

## 本地状态与资料边界

`agent-dev/state/` 只保存本机 `environment.json`、可重建索引和轻量依赖使用笔记。该目录不进入插件 JAR，默认不提交版本控制，也不保存第三方归档、解包资料或反编译文本。

目标项目 Gradle 管理主 JAR、sources/Javadoc 的本机缓存；索引记录它们的路径与哈希。实现阅读优先直接读取单个 `sources.jar` 条目，缺少 sources 时才临时下载 Vineflower 反编译指定主 JAR，并在工具退出时清理。归档或 Snapshot 哈希变化、依赖集合变化、重定位变化或笔记变更条件满足时，相关结论必须重新复核。

最终分发的文档/Skill 不携带第三方归档，以避免版权、体积和过期问题。

## 无资料时的行为

未取得或无法查询资料时：

1. 说明需要的精确构件或服务端版本；
2. 列出已查询的索引、Gradle 资料路径、sources/Javadoc 或临时反编译来源；
3. 不实现依赖该未知接口的代码；
4. 提出可验证的替代：同步资料、降级为已证实 API、缩小版本范围，或让用户确认环境；
5. 不生成“可能存在”的方法名、反射字符串或空实现。

## 验证不是一次性的

升级 Minecraft、API、PluginBase、主要依赖或 Snapshot 内容时，涉及范围的旧证据都需重新验证。构建通过只证明当前编译类路径可解析，不能替代源码/Javadoc 查询和目标服务端启动验证。
