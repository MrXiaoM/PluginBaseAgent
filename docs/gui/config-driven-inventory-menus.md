# 配置驱动箱子容器菜单

本文讨论由 YAML 定义标题、箱子格子布局和图标，再由 Java 创建运行期菜单实例的 Minecraft `Inventory` 菜单。它仍是服务端箱子容器界面，不是客户端原生 GUI；YAML 是**菜单模型**，不是可以绕过业务安全边界的脚本语言。

适合将布局、装饰图标、可本地化文字、静态按钮或可由服主维护的菜单列表交给配置的场景。菜单业务状态、权限、库存事件安全、事务、异步 I/O、数据校验和生命周期仍由 Java 负责。

对全部布局和交互均由 Java 固定的菜单，改读 `hardcoded-inventory-menus.md`。

## 实现前必须取证

计划阶段必须先做以下工作：

1. 从 `pluginBaseModules` 确认实际启用的模块。配置箱子菜单至少需要 `gui`；按实际功能再确认 `actions`、`l10n`、`paper`。不要读取、推断或记录 `LibrariesResolver-Gradle` 的隐式版本。
2. 按 `../evidence/dependency-index-zoo-tool.md` 或 `../evidence/dependency-index-cli.md` 查询项目实际解析的 GUI 构件，定位 `AbstractGuiModule`、`AbstractGuisModule`、`LoadedIcon` 与计划调用的成员；需要完整实现语义时，再按 `../evidence/query-playbook.md` 直接读取同版本 `sources.jar`。不要猜测其它版本的配置字段或 Java 签名。
3. 若配置图标点击后使用 Action，确认实际已解析的 `actions` 构件；若使用语言 Holder 或可重载用户消息，确认 `l10n` 构件。仅在构建脚本确实启用模块时继续；不要因 `gui` 已存在而假设其它模块能力可用。
4. 阅读目标项目已有的菜单 YAML、加载器、图标模型、Action Provider 和语言 Holder。框架源码只说明通用容器模型、图标和事件边界；它没有替代项目特定菜单的完整示例或业务规则。

资料不完整时，停在设计阶段。不得从别的项目复制 YAML 字段、Action 名称或语言键后假定它们适用于当前版本和当前项目；查询失败不得自动同步。

## 三个模块的职责边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `gui` | `Inventory` 箱子容器、顶部 Holder、布局字符、图标模型、打开/关闭/点击/拖拽路由 | 业务权限、数据库事务、页面数据正确性、任意配置动作的安全性 |
| `actions` | 解析并执行已注册的 `IAction` 列表、替换参数、延迟动作等已验证能力 | 定义菜单 slot、持有菜单会话、保证点击幂等、替代权限或金额校验 |
| `l10n` | 可重载的用户消息/语言键与消息格式化 | 管理 YAML 菜单模型、决定哪些格子可点、替代 Placeholder/业务数据替换 |

三者可以组合，但不能互相替代：

- 菜单模型决定“哪个 slot 显示和触发哪个图标”；运行期实例决定“该玩家这次打开时是否有权限、数据是否有效、点击能否执行”。
- Action 只能在 Java 已完成权限、状态、金额/物品/数据库前置条件之后执行；配置动作不能成为绕过核心业务校验的入口。
- L10n 用于可本地化的提示、错误和反馈；菜单标题、Lore 或图标配置是否使用语言消息，必须由项目已有格式和对应模块资料确定。
- Action 或语言重载后，不能假定所有已打开菜单自动安全刷新。明确关闭、重开、刷新或版本失效策略。

## YAML 菜单模型

PluginBase `AbstractGuiModule` / `AbstractGuisModule` 采用字符布局模型。常见结构如下：

```yaml
title: '示例菜单'
inventory:
  - '框框框框框框框框框'
  - '框　一　　　　　框'
  - '框框框框框框框框框'
main-icons:
  一:
    # 由项目定义的主要业务图标模型
other-icons:
  框:
    material: WHITE_STAINED_GLASS_PANE
    display: '&f '
```

含义与约束：

- `inventory` 每个字符代表顶部箱子容器中的一个 slot；每行必须符合当前项目和目标库存类型要求，不能把字符数或行数当作自动容错数据。
- 空格/全角空格在框架抽象中表示空 slot；其它字符需能映射为 `main-icons` 的业务图标或 `other-icons` 的通用图标。
- 同一个字符可多次出现。运行期实现必须按当前出现次数、slot 或模型规则决定显示哪个业务图标，不能假定字符 ID 在一页中唯一。
- `title`、图标材质、名称、Lore、NBT、模型数据和 Placeholder 的准确字段及跨版本语义必须由当前模块/API 资料和项目已有配置确认。
- YAML 是管理员输入，应对缺失、重复 ID、未知图标、错误材质、无效操作和不合法布局给出可诊断警告；不能静默构造半可用菜单。

不要将用户可编辑 YAML 直接映射成任意 Java 类名、反射调用、控制台命令或未审查的外部动作。

## 单菜单与多菜单模型

### `AbstractGuiModule`：单个固定配置菜单

适用于插件内有一个职责稳定、资源路径固定的菜单，例如一个编辑页、预览页或固定商店页。子类在重载时读取一个 YAML 文件，保存标题、字符布局、主要图标和其它图标，并创建该菜单的每玩家 `Gui` 实例。

子类负责：

- 指定固定资源/数据目录路径和配置加载策略；
- 解释 `main-icons` 中项目特有的业务字段；
- 为当前玩家、slot、出现次数和运行期数据生成主要图标；
- 将点击 ID 路由到明确业务逻辑，并定义关闭、刷新和错误路径。

### `AbstractGuisModule`：多个同一模式的配置菜单

适用于管理员可在某个目录增加多个菜单 YAML，或同一模型有多个 ID，例如自定义商店、任务菜单组或活动菜单。该抽象在重载时清空旧模型，以不区分大小写的 ID 保存模型；项目加载器负责从目录读取每个文件、拒绝重复 ID，并通过模型提供器解析为项目的 `IModel`。

需要明确：

- 菜单 ID 的来源、大小写规则、权限和命令/Action 打开路径；
- 新旧配置模型替换时，已打开菜单的策略；推荐关闭相关旧实例，或建立可验证的模型版本失效机制；
- 模型是可共享的不可变/重载替换对象，玩家会话状态放在每个 `Gui` 实例；
- 目录中新建、删除、重命名或配置损坏后的回退与日志策略；
- 菜单间跳转时传递的父实例或稳定参数，不以全局可变字段保存玩家导航栈。

配置菜单管理器应在重载前关闭或明确使已打开的旧菜单实例失效，再清空并重新加载共享模型；这是“替换模型不能遗留旧界面”的必要边界，不要求所有项目使用相同目录、类名或权限字段。

## 运行期菜单实例与事件

无论模型来自 YAML 还是 Java，每位玩家每次打开都创建独立的 `IGuiHolder`/`Gui` 实例。实例持有玩家、当前模型、页面、筛选条件、父菜单、点击锁和本次会话的数据快照；共享模型不保存这些可变字段。

点击处理至少遵守：

1. 先根据顶层容器和有效 slot 确认事件属于当前菜单；
2. 默认取消不允许的顶部/玩家背包交互，并为输入槽逐项定义例外；
3. 由布局字符、出现次数和当前模型定位主要图标或其它图标；
4. 主要图标执行项目业务逻辑，通用其它图标可在已验证前置条件下调用其配置动作；
5. 非幂等操作加点击锁/事务状态，异步查询或数据库完成后回到框架调度器，再验证玩家、打开实例和模型仍有效；
6. 拖拽、关闭、玩家退出、重载和停用必须使旧会话和异步回调安全失效。

分页、定时刷新和父菜单返回是项目层行为。它们可复用字符布局和图标模型，但必须有每实例页面状态、刷新频率边界、玩家在线检查和关闭后的失效策略。

## 图标、动作和语言

`LoadedIcon` 提供通用图标配置与点击动作接入，但其可用字段、材质提供器、NBT 行为和已注册 Action Provider 仍必须按当前模块资料查询。使用时：

- 装饰图标与业务图标分开；前者可由 `other-icons` 生成，后者由项目模型根据玩家/数据生成；
- 物品图标若需自定义 NBT，且项目已安装 `item-nbt-api`，按 `../external-libraries/item-nbt-api.md` 使用适配层中的 `NBT.get(...)`/`NBT.modify(...)`，不使用已弃用的 `NBTItem` 路径或 PDC 作为替代；
- Action 列表必须只引用当前项目已注册且已查询的动作类型；敏感操作仍由 Java 在执行前校验；
- 面向玩家的成功/失败消息使用项目的 L10n 约定；不要在 YAML、Action 和 Java 中复制分散且不可重载的同一条文本；
- 任何 Placeholder、替换参数或语言参数都视为输入边界，不能拼接为未经审查的命令或数据库查询。

## 重载与最低验证

配置菜单重载时，至少验证：

- 配置目录、默认资源保存、文件 ID、重复项和解析失败日志；
- 已打开菜单的关闭/刷新/失效策略；
- 新模型只影响之后创建的实例，或已打开实例有明确、可测试的更新策略；
- 点击、拖拽、关闭、退出、父子菜单、分页和重复点击；
- Action、L10n、权限、可选依赖和 Placeholder 在缺失或错误输入时的回退；
- `python agent-dev/tools/verify_plugin_project.py --project .`、Gradle Wrapper 构建、最终 JAR 检查和目标服务端手工验证。

不要以“YAML 能加载”替代菜单可用性验证。至少手测正常配置、缺失图标、无权限玩家、错误 Action、重载期间打开、关闭后异步完成及分页/返回路径。
