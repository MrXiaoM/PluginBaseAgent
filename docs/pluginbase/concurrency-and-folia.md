# 调度、线程与 Folia 边界

`plugin.yml` 中的 `folia-supported: true` 不是功能开关，也不是对任意并发代码的保证。它表示插件声明支持 Folia；每一处任务调度、玩家/实体/世界访问、共享状态和外部 I/O 都仍需按目标服务器与 API 的实际线程规则设计和验证。

PluginBase 提供调度抽象以适配 Bukkit 与 Folia 路径。项目应优先通过主类 `getScheduler()` 获取调度器，而不是在业务模块中散落对 Bukkit 全局调度器的直接调用。

## 基本原则

1. 先判定操作对象：纯计算、文件/网络/数据库 I/O、玩家/实体、区块/世界、库存、配置状态或跨线程共享数据。
2. 先查询目标 Spigot/Paper/Folia 与 PluginBase 版本资料，确认该操作允许的线程和调度形式。
3. 优先通过 `plugin.getScheduler()` 安排延迟、周期和异步任务。
4. 业务逻辑不可假设“主线程”在 Folia 中等同于所有实体和区域的安全上下文。
5. 不允许异步任务直接读写未经验证的 Bukkit、Paper、Inventory、ItemMeta、Entity、World 或配置对象。
6. 任务、回调和资源必须在插件停用时可取消、可停止或安全失效。

## PluginBase 调度器

`BukkitPlugin` 初始化调度器时会优先尝试加载兼容实现；不可用时回退 Bukkit 调度实现。项目使用：

```java
IRunTask task = plugin.getScheduler().runTaskTimer(this::onSecond, 20L, 20L);
```

准确可用方法、任务返回类型、参数含义和线程语义以当前 `IScheduler`、Bukkit/Folia 实现源码或 Javadoc 为准。不要仅凭其它项目示例假定存在某个异步、实体或区域调度方法。

周期任务应保存返回的任务句柄，并在合适的停用路径取消；框架会在主类停用过程中取消其调度器任务，但项目仍应避免任务体继续使用已关闭的模块、数据库或缓存。

## 推荐分层

| 工作类型 | 推荐做法 | 禁止或高风险做法 |
| --- | --- | --- |
| 纯计算 | 在已验证的异步/后台路径计算；只传递不可变输入 | 在主线程执行不可控的大型计算。 |
| 文件、HTTP、数据库 I/O | 后台执行；将结果转换为纯数据后，在正确上下文应用 | 在玩家交互、事件回调或主线程同步等待网络/数据库。 |
| 玩家消息、库存修改 | 回到目标 API 要求的正确调度上下文 | 从异步线程直接调用未验证的 Bukkit/Paper 方法。 |
| 实体、区块、世界操作 | 按目标服务端的实体/区域调度规则安排 | 假设一个全局主线程能安全覆盖所有 Folia 区域。 |
| 配置重载 | 构造新状态后原子替换或按模块策略更新 | 多线程同时原地修改可变配置对象。 |
| 缓存与集合 | 使用明确同步策略、不可变快照或线程安全容器 | 在异步与事件线程无保护地读写普通集合。 |

## 延迟和周期任务

- 明确 tick、毫秒和现实时间的区别；服务器卡顿会影响 tick 驱动任务的实际间隔。
- 周期任务应检查插件/模块是否仍处于有效状态；不让旧任务在重载后继续使用旧配置。
- 长周期业务逻辑应分解，避免每次运行遍历全部在线玩家、世界或大型数据集合而无上限。
- 不将周期任务当作修复竞态条件的手段；先建立正确同步模型。
- 计划“服务器完全启动后”的工作优先使用框架 `afterServerLoaded()` 的既定时机，而非任意延迟猜测。

## 重载和停用

配置重载与插件停用可与后台任务交错。设计时必须：

1. 在重载前后定义哪些状态可被任务读取；
2. 通过版本号、不可变快照、取消句柄或锁防止旧任务提交过期结果；
3. 在 `beforeDisable()` 取消项目任务、停止工作队列、拒绝新操作；
4. 避免在 `afterDisable()` 调度新任务或访问已关闭数据库；
5. 对外部回调检查插件/模块状态，避免插件卸载后回调重新访问 Bukkit API。

## Folia 声明检查

在保留或新增 `folia-supported: true` 前，逐项审查：

- 是否仍直接使用 Bukkit 全局调度器；
- 是否有异步任务直接访问玩家、世界、实体或库存；
- 是否有跨区域实体/区块逻辑；
- GUI、监听器、命令和定时器是否只在已验证的上下文操作 Bukkit 对象；
- 数据库/HTTP 完成回调是否正确切换回所需上下文；
- 所用 PluginBase 版本是否包含与当前服务端兼容的调度模块。

有任一项缺乏资料或测试时，不得把 Folia 兼容性宣称为已验证；应记录范围并要求目标服务端验证。
